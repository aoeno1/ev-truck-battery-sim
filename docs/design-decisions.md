# 设计决策日志（从真实对话提炼）

> 本文件记录 `ev-truck-battery-sim` 的完整需求演进：每一轮用户反馈 → 关键决策 → 依据。它展示了这个 skill 是如何从真实使用中提炼出来的，也是后来者理解"为什么这么做"的唯一材料。已脱敏。

## 第一轮 · 从 skill 调研回归真实需求

- **起点**：调研 GitHub 上同类型 skill（新能源/动力电池方向），确认现成"解剖/爆炸图"工具均为成品渲染器，非可配置的生成器。
- **决策**：放弃外部 skill，回归真实需求——展示重卡电池系统组成 + 三态运行（行驶放电/刹车回收/热管理）。
- **依据**：需求本质是"讲组成 + 讲逻辑"，不需要照片级渲染；自研单文件 HTML 最可控且符合离线交付偏好。

## 第二轮 · 升级为可交互仿真

- **反馈**：点击更换电池包（磷酸铁锂/三元/固态/钠离子），电量/续航/充电速率联动；**重量必须互相耦合**（电量多→车重→续航减）；叠加温度影响；CTB 单包设计。
- **决策**：建立三条耦合链（电量→续航一阶；重量→滚阻二阶；温度→容量+温控功耗+充电倍率三阶），状态量电池温度 Tb 独立推进。
- **依据**：用户点名"电量多了车重了续航就会减少"——二阶耦合是演示的灵魂，不可省。

## 第三轮 · 布置纠偏 + 单页化 + 踏板交互

- **反馈 ①**：液冷机组应为**集成式、置于驾驶室前进风口**，高压箱置于**座椅下**（行业常规布局）；电池包长度减 50%、内部 4 模组；所有内容一屏不滚动。
- **反馈 ②**：无用的描述不要常驻，做悬停显示；制动/加速/充电三踏板同尺寸不同色（充电功率直接选），逻辑一致；要 iOS 风格。
- **决策**：
  - 按常规布置重排——车架纵梁上方完整释放给货箱，这个收益点成为布置讲解的核心；
  - 所有静态说明收进 hover tooltip（触屏 click 触发）；
  - 弃用正负滑杆（用户反馈"难理解"），改按压式踏板 + 功率直选；
  - iOS 规范落地：系统色（#007AFF/#34C759/#5856D6）、8pt 栅格、系统字体栈。
- **依据**：一屏完成所有操作是硬约束；"同尺寸不同色"保证三个控件肌肉记忆一致。

## 第四轮 · 充电逻辑纠错 + 数据核查锁定

- **反馈 ①**：充电逻辑有错——LFP/三元/固态快充都限制 SOC 范围，钠电窗口宽；**只有钠电充电基本不需要开热管理，其他电池关了热管理快充很快温度报警**。
- **反馈 ②**：窄屏布局优化；各体系数据与市面公布数据逐项核查，基本结论先锁死（能量密度/能耗/续航/可用 SOC 区间/低温性能）。
- **决策**：
  - 引入分体系 SOC 窗口 + BMS 门限状态机（低温禁充/热报警/停充）+ 化学体系热损系数。钠电 −20℃ 关热管理 600kW 免预热的正例，与 LFP 25℃ 600kW 约 30 分钟报警的反例，成为演示最有说服力的一组对照；
  - 数据逐项对标：固态 280→**320** Wh/kg（装车区间 300–380 下沿偏中）、钠电 131→**140**（电芯 175×成组 80%）、三元 190→**200**，连带倍率与 SOC 窗口修正、固态/钠电低温曲线上调；
  - 布局改三档响应式（≥1200 / 780–1199 / <780），14 视口实测零滚动。
- **依据**：用户是电芯评测专业背景，对"逻辑错误"和"数据出处"极其敏感——模型必须同时经得起物理推演和市面对标。

## 贯穿全程的方法论沉淀（本 skill 的核心）

1. **矢量 SVG 而非 AI 生图**：部件位置精确、标签不干涉、零依赖、无限清晰。对"示意图"场景，AI 生图反而更慢更不可控。
2. **量纲手算复核**：滚阻项漏乘 1000 m 距离因子导致续航虚高 3.8 倍——能量公式必须两条路径交叉验证。
3. **验证钩子先行**：headless 环境 rAF 不触发，不暴露 `__sim.step()` 就没有回归能力；60 倍单位 bug 靠轨迹回归抓出。
4. **数据先锁后写**：四个基准数错一个，全部派生结论（续航/充电时长/对比条）全错。
5. **信息分层**：静态说明悬停化、实时值仪表化、对比条归一化——一屏承载全部信息的前提。
